# Adico DOS

A compact, bootable x86_64 toy operating system written in C and x86_64 assembly.
It takes its **minimalism** from Q-DOS (86-DOS): one small, readable code base, no
layers for their own sake. It takes its **semantics** from POSIX: a single `/` file
hierarchy, file descriptors 0/1/2, `errno`, exit statuses, process groups, signals,
pipes and a Unix-style shell. There are no drive letters, FCBs or FAT quirks.

```
adico:/home# ls /bin | wc -l
     45
adico:/home# yes | head -n 2
y
y
adico:/home# crash
Segmentation fault
```

## 2. Quick start

```sh
# Debian/Ubuntu
sudo apt install build-essential qemu-system-x86

make            # builds adico.elf, adico32.elf and a blank 8 MiB adico.img
make run        # boots in QEMU with the console on your terminal
```

Leave QEMU with **Ctrl-A, then X**, or type `poweroff` inside Adico DOS (that one also
saves your files, see [Section 11](#11-file-system-and-persistence)).

## 3. Repository layout

The whole OS lives in exactly three source files, plus the build file.

```
adico_boot.S     x86_64 entry, long-mode switch, GDT, ISR stubs, port I/O,
                 context switch, memcpy/memset/memmove
adico_kernel.c   kernel: heap, console, TTY, timer, ATA, RAM file system, pipes,
                 tasks, signals, system calls, disk snapshot, traps, kmain
adico_posix.c    POSIX layer: syscall stubs, libc subset, shell (sh), utilities
Makefile         build, run, test, ISO, consistency checks
```

Files generated by `make`: `*.o`, `adico.ld` (the linker script), `adico.elf`,
`adico32.elf`, `adico.img` (the disk image) and, with `make iso`, `adico.iso`.

### Map of `adico_kernel.c`

| # | Section | # | Section |
|---|---|---|---|
| 1 | Shared ABI | 8 | TTY line discipline and keyboard |
| 2 | Library core (`str*`, `vsnprintf`) | 9 | RAM file system (VFS) |
| 3 | Heap allocator | 10 | Pipes and open file descriptions |
| 4 | Console (VGA + COM1), `kprintf` | 11 | System calls |
| 5 | Clock (PIT, CMOS RTC) | 12 | Disk snapshot (persistence) |
| 6 | ATA PIO disk driver | 13 | Traps: IDT, PIC, exceptions, IRQs |
| 7 | Tasks, signals, scheduler | 14 | `kmain` |

### Map of `adico_posix.c`

1. Shared ABI (a byte-identical copy of the kernel's block)
2. System call stubs (`int 0x80`) and `errno`
3. libc subset (`malloc`, the `printf` family, `strtol`, `qsort`, helpers)
4. POSIX shell (`sh`)
5. Utilities installed in `/bin`
6. Program table (`posix_progs[]`) and the init entry point

The only code the two C files share at link time is a tiny string and `printf` core
defined in the kernel (`strlen`, `strcmp`, `strncmp`, `strchr`, `strcpy`, `strncpy`,
`memcmp`, `vsnprintf`, `snprintf`). Everything else crosses the boundary through
system calls.

## 4. Build system

### Requirements

| Tool | Notes |
|---|---|
| `gcc` (x86_64) | Tested with GCC 13. Also assembles the `.S` file |
| GNU binutils (`as`, `ld`, `objcopy`) | `objcopy` re-wraps the image as ELF32 for QEMU |
| GNU `make` 4.0 or newer | The linker script is generated with `$(file ...)` |
| `bash` | Only for `make abi-check` |
| `qemu-system-x86_64` | To run it |
| `grub-mkrescue` and `xorriso` | Optional, only for `make iso` |

No cross compiler is needed: everything is built freestanding with the host toolchain.

### Compiler flags

```
-m64 -ffreestanding -fno-pie -no-pie -mno-red-zone -mgeneral-regs-only
-fno-stack-protector -fno-asynchronous-unwind-tables
-fno-tree-loop-distribute-patterns -O2 -Wall -Wextra -std=gnu11
```

* `-mno-red-zone`: interrupts run on the interrupted stack in ring 0.
* `-mgeneral-regs-only`: the kernel never initializes FPU or SSE state.
* `-fno-tree-loop-distribute-patterns`: keeps GCC from turning loops into calls to
  routines that do not exist.

### Targets

| Target | What it does |
|---|---|
| `make` / `make all` | Builds `adico.elf`, `adico32.elf` and a blank `adico.img` |
| `make run` | QEMU with `-nographic` (serial console on your terminal) |
| `make run-gui` | QEMU with a VGA window plus the serial console on stdio |
| `make test` | Scripted smoke test through the serial console |
| `make iso` | Builds `adico.iso` with GRUB (needs `grub-mkrescue`) |
| `make abi-check` | Verifies both C files carry the identical shared ABI block |
| `make lines` | Prints line counts |
| `make clean` | Removes object files, the linker script, both ELF files and the ISO |

`make clean` deliberately keeps `adico.img`, because it is your persistent disk. Delete
it yourself (`rm adico.img`) to start over with an empty one.

### Why two ELF files?

QEMU's `-kernel` Multiboot loader refuses 64-bit ELF images. `adico.elf` is the real
64-bit link result; `adico32.elf` is the same content re-wrapped with
`objcopy -O elf32-i386`. The entry code and Multiboot header are 32-bit anyway, and the
kernel switches to long mode itself. Always boot `adico32.elf`.

### Linker layout (generated `adico.ld`)

```
0x100000  .multiboot, .text      (header must stay in the first 8 KiB of the file)
          .rodata, .data
          .bss = [ .bootbss: page tables + boot stack ][ C bss ]   only the C bss is cleared
          __kernel_end            the heap starts at the next 4 KiB boundary
```

## 5. Running and testing

### Manual runs

```sh
make run                     # terminal console, Ctrl-A X quits QEMU
make run-gui                 # VGA window for keyboard input, serial on stdio
```

The equivalent raw command:

```sh
qemu-system-x86_64 -kernel adico32.elf -m 128M \
    -drive file=adico.img,format=raw,if=ide -nographic
```

* The disk must be on the **primary IDE master** (`if=ide`); the driver is a polled
  ATA PIO driver for that one device.
* Without a disk the system still boots; it just cannot persist files.
* Input works from both the PS/2 keyboard (VGA window) and COM1 (terminal). In
  `-nographic` mode Ctrl-C is delivered to the guest, not to QEMU. In `run-gui` mode the
  *terminal's* Ctrl-C would kill QEMU, so type into the VGA window instead.

### Smoke test

```sh
make test
```

Boots the system, types `echo smoke-test-ok`, `uname -a`, `ls /bin | wc -l` and
`poweroff` through the serial port, and checks that the marker text came back. It uses
fixed `sleep` delays, so on a slow host you may need to raise them in the `Makefile`.
This target has not been run by the author yet.

### Suggested manual test plan

```sh
help                          # built-ins
ls -l /bin                    # utilities, mode 0755
echo hello > /tmp/a.txt ; cat /tmp/a.txt
ls /bin | wc -l               # pipe
yes | head -n 3               # SIGPIPE terminates 'yes'
sleep 30                      # press Ctrl-C: returns with status 130
echo $?
crash                         # "Segmentation fault", $? is 139
kill -9 1234                  # "No such process"
sh /home/hello.sh world       # script with an argument
mkdir -p /tmp/a/b/c && rm -r /tmp/a
echo data > /home/note && sync && poweroff
# boot again: /home/note is still there
```

## 6. Using the system

At boot the kernel prints a short log and starts `init` (pid 1), which is the shell. It
runs `/etc/profile`, prints `/etc/motd` and shows a prompt:

```
adico:/home#
```

### Keyboard and terminal

| Key | Effect |
|---|---|
| Enter | Submits the line (a terminal sends CR; the TTY converts it to LF) |
| Backspace | Erases one character |
| Ctrl-U | Erases the whole line |
| Ctrl-C | Echoes `^C`, sends `SIGINT` to the foreground process group |
| Ctrl-D | On an empty line: end of input (EOF). Otherwise: submits the partial line |

The TTY is a canonical-mode line discipline: lines are limited to 255 characters, echo
is on, and there is no history or cursor-key editing (arrow keys are ignored).

The console writes every byte to both VGA text mode (80x25) and COM1. On VGA a small
ANSI subset is understood (`ESC[2J` clear, `ESC[H` and `ESC[r;cH` cursor positioning).
Other escape sequences, such as colors, are ignored on VGA but passed through to a
serial terminal, which is why the prompt is colored in a terminal and plain on VGA.

### Default file tree

```
/            root (RAM file system)
|-- bin/     one executable entry per utility (created at every boot)
|-- dev/     console tty null zero urandom
|-- etc/     motd hostname profile
|-- home/    hello.sh   (the shell's starting directory)
`-- tmp/
```

There is a single user (root) with a fixed umask of `022`.

## 7. Shell reference

`/bin/sh` is a POSIX-flavored shell. The init shell and `sh` share one implementation.

### Running commands

```sh
cmd arg...                    # looked up through $PATH (default /bin)
/bin/ls  ./prog  ../x/prog    # names containing '/' skip the PATH search
cmd1 | cmd2 | cmd3            # pipeline; each stage is its own task
cmd1 && cmd2    cmd1 || cmd2  # conditional lists, left associative
cmd1 ; cmd2                   # sequence
cmd &                         # background job; prints "[n] pid"
```

Exit statuses follow POSIX: `0` success, `127` command not found, `126` found but not
executable, `128+N` terminated by signal `N` (so `130` for Ctrl-C and `139` for a
segmentation fault). `$?` holds the last status.

### Redirection

| Syntax | Meaning |
|---|---|
| `< file` | stdin from file |
| `> file`, `>> file` | stdout truncate / append |
| `2> file`, `2>> file` | stderr truncate / append |
| `2>&1` | stderr to wherever stdout goes (applied after the other redirections) |

### Expansion and quoting

* `'single quotes'` are literal. `"double quotes"` allow `$` expansion and `\$ \" \\`.
  A backslash outside quotes escapes the next character.
* `$VAR`, `${VAR}`, `$?` (last status), `$$` (shell pid), `$#` (argument count),
  `$0` to `$9` (script name and arguments).
* `~` at the start of a word expands to `$HOME`.
* Globbing with `*` and `?` in the **last path component only** (`/bin/c*` works,
  `/b*/ls` does not). Names starting with `.` match only a pattern that starts with `.`.
  A pattern with no match is left unchanged.
* An unquoted expansion that is empty disappears; a quoted one stays as an empty
  argument. There is no field splitting after expansion.

### Built-ins

| Built-in | Description |
|---|---|
| `cd [dir]` | Change directory (default `$HOME`); updates `$PWD` |
| `exit [n]` | Leave the shell. Leaving the init shell powers the machine off |
| `export NAME[=value]` | Mark a variable for export to child programs; with no arguments, lists them |
| `unset NAME...` | Remove variables |
| `set` | Print all variables |
| `wait` | Wait for all children |
| `. file`, `source file` | Run a script in the current shell |
| `help` | Short summary |
| `NAME=value` | Assignment as a whole command (prefix assignments before a command are not supported) |

Built-ins run inside the shell only when they are a single, foreground command; they do
not take part in pipelines.

### Job control and signals

* Interactive shells ignore `SIGINT`. Each pipeline gets its own process group, which
  becomes the terminal's foreground group while it runs, so Ctrl-C reaches exactly
  those programs.
* Background jobs are not affected by Ctrl-C. Finished jobs are reported as
  `[n] Done (...)` before the next prompt. There is no `fg`, `bg` or `jobs`.
* A non-interactive shell (script or `sh -c`) keeps its children in its own group, so
  Ctrl-C terminates the whole script.

### Scripts

```sh
sh /home/hello.sh world        # always works
sh -c 'echo $0; ls /bin'       # one-liner
echo 'echo hi' | sh            # commands from stdin
```

A script can also be executed directly once it has the execute bit:

```sh
echo 'echo running' > /tmp/x.sh
chmod 755 /tmp/x.sh
/tmp/x.sh                      # the kernel answers ENOEXEC; the shell then runs it with /bin/sh
```

Comments start with `#`. There are no `if`, `for`, `while`, `case`, functions,
here-documents, `$(...)` or arithmetic expansion; chain commands with `&&`, `||` and
`test` / `[` instead.

## 9. Architecture

### 9.1 Boot sequence

1. The **loader** (QEMU `-kernel` or GRUB `multiboot`) loads the image at 1 MiB and
   jumps to `_start` in 32-bit protected mode with `EAX` = Multiboot magic and
   `EBX` = info pointer.
2. `adico_boot.S` checks CPUID for long mode, builds page tables that identity-map the
   first **4 GiB with 2 MiB pages**, enables PAE, loads `CR3`, sets `EFER.LME`, enables
   paging, loads a 64-bit GDT (null, code `0x08`, data `0x10`) and far-returns into
   64-bit code. A CPU without long mode prints `ERR:46-B` on VGA and halts.
3. The 64-bit entry reloads the data segments, sets up the boot stack, clears the C
   `.bss` and calls `kmain(magic, mbi)`.
4. `kmain` initializes serial and VGA, the heap (sized from the Multiboot memory info,
   default about 64 MiB, capped at 1 GiB), IDT, PIC, PIT (100 Hz), RTC, ATA, the RAM
   file system and the disk snapshot. It then creates the `init` task and starts the
   scheduler. The boot context is never resumed.

### 9.2 Memory

| Range | Use |
|---|---|
| `0xB8000` | VGA text buffer |
| `0x100000` (1 MiB) | Kernel image |
| `__kernel_end` to the end of RAM | Kernel heap: task stacks, inodes, file data, pipes, program memory |
| 0 to 4 GiB | Identity mapped, supervisor, writable |

There is one address space and no memory protection: everything runs in ring 0. The
heap is a first-fit allocator with forward coalescing. Each task gets a 64 KiB stack.
Program memory (`malloc`) comes from an anonymous `mmap` that the kernel tracks per
task and frees when the task exits, so a program cannot leak memory past its lifetime.

### 9.3 Interrupts and traps

| Vector | Handling |
|---|---|
| 0 to 31 | CPU exceptions. In a task: print a message, then terminate that task with `SIGFPE` (vector 0), `SIGILL` (6) or `SIGSEGV` (all others). In the boot context, or on a double fault: kernel panic with a register dump |
| 32 (IRQ0) | PIT tick at 100 Hz; wakes sleepers and polls COM1 |
| 33 (IRQ1) | PS/2 keyboard (scan code set 1, US layout, Shift/Ctrl/Caps) |
| 36 (IRQ4) | COM1 receive |
| 0x80 | System calls (trap gate, interrupts stay enabled) |

The PIC is remapped to vectors `0x20` to `0x2F`.

### 9.4 Tasks and scheduling

Every program is a **cooperative kernel task** with its own stack, file descriptor
table (16 entries), working directory, process group, pending-signal mask and ignore
mask. A context switch (`ctx_switch` in assembly) saves the callee-saved registers and
swaps stacks.

* A task gives up the CPU only when it **blocks**: `read` on an empty pipe or TTY,
  `write` to a full pipe, `waitpid`, `nanosleep`, or exit. Scheduling is round robin.
* When nothing is runnable the CPU idles with `sti; hlt`.
* Up to 31 tasks can exist at once (slot 0 is the boot context).
* A task that exits becomes a zombie until its parent reaps it with `waitpid`. Orphans
  are adopted by `init`. If `init` exits, the system syncs the disk and powers off.

> There is **no preemption**. A program that loops forever without making a system call
> hangs the whole machine, and Ctrl-C cannot interrupt it, because signals are delivered
> when a task makes or leaves a system call.

### 9.5 Process creation: `spawn`, not `fork`

Without an MMU, `fork` cannot give a child its own address space, so Adico DOS uses a
`posix_spawn`-style call:

```c
pid_t spawn(const char *path, char *const argv[], char *const envp[],
            const struct spawn_attr *attr);

struct spawn_attr { int fd[3]; int pgid; };
```

* `attr.fd[0..2]` name **parent** descriptors that become the child's 0, 1 and 2. The
  child receives *only* those three, so no pipe ends leak and EOF detection works.
* `attr.pgid`: `> 0` join that group, `< 0` start a new group, `0` inherit.
* Signal dispositions are reset to default in the child; the working directory is
  inherited.
* The target must be a regular file with an execute bit. Built-in programs have a kernel
  entry point; any other file yields `ENOEXEC` (the shell then runs it as a script).
* The child's `main` is `int main(int argc, char **argv, char **envp)`; returning from it
  is the same as calling `exit` with that value.

### 9.6 Signals

Signals use POSIX numbers for the supported set: `SIGHUP 1`, `SIGINT 2`, `SIGQUIT 3`,
`SIGILL 4`, `SIGABRT 6`, `SIGFPE 8`, `SIGKILL 9`, `SIGSEGV 11`, `SIGPIPE 13`,
`SIGTERM 15`, `SIGCHLD 17`.

* Each signal is either default (terminate the task) or ignored (`SIG_IGN`).
  `SIGKILL` cannot be ignored. User-defined handlers are not supported.
* Delivery happens when a system call returns, or when a blocked call is interrupted
  (it then returns `-EINTR`).
* `SIGCHLD` is never delivered.
* Writing to a pipe with no readers raises `SIGPIPE` and returns `EPIPE`.
* `waitpid` statuses use the POSIX encoding: a normal exit is `(code & 0xFF) << 8`; a
  task killed by signal `N` has `N` in the low 7 bits. `WIFEXITED`, `WEXITSTATUS` and
  `WTERMSIG` are defined in the ABI block.

### 9.7 Terminal and process groups

`/dev/console` and `/dev/tty` are the same device. The kernel keeps one *foreground
process group* for it, and Ctrl-C signals that group. A program sets or reads it with
`ioctl(fd, TIOCSPGRP / TIOCGPGRP, &pgid)`. A successful `TIOCGPGRP` is also how
`isatty()` is implemented.

### 9.8 How Q-DOS minimalism meets POSIX

| Aspect | Q-DOS spirit | POSIX behavior in Adico DOS |
|---|---|---|
| Code size | A few thousand lines, readable in an afternoon | Three source files |
| Storage | Simple and direct | One `/` tree; `sync` snapshots it to a raw disk |
| API | A handful of direct calls | `open read write close lseek stat ...` with `errno` |
| I/O | The console as a device | `/dev/console`, descriptors 0/1/2, LF line endings |
| Programs | Small commands | `/bin/*` with `argc/argv`, exit statuses, pipes |

## 10. System call reference

Calls use `int 0x80` with the Linux x86_64 register convention: number in `rax`,
arguments in `rdi, rsi, rdx, r10, r8, r9`, result in `rax`. A negative result is
`-errno`. The numbers are Linux's wherever a Linux equivalent exists. The wrappers in
`adico_posix.c` set `errno` and return `-1` on failure, like libc.

| Nr | Name | Notes |
|---:|---|---|
| 0 | `read(fd, buf, n)` | Files, pipes, devices; the TTY returns one line at a time |
| 1 | `write(fd, buf, n)` | Honors `O_APPEND`; pipes block when full |
| 2 | `open(path, flags, mode)` | `O_RDONLY O_WRONLY O_RDWR O_CREAT O_EXCL O_TRUNC O_APPEND O_DIRECTORY` |
| 3 | `close(fd)` | |
| 4 | `stat(path, st)` | Fills `struct stat` (there are no symlinks, so no separate `lstat`) |
| 5 | `fstat(fd, st)` | Kernel only; no libc wrapper yet |
| 8 | `lseek(fd, off, whence)` | `ESPIPE` on pipes and devices |
| 9 | `mmap(...)` | Anonymous and zero-filled; only the length argument is used |
| 11 | `munmap(addr, len)` | Frees a block returned by `mmap` |
| 16 | `ioctl(fd, req, arg)` | `TIOCGPGRP`, `TIOCSPGRP` on the TTY |
| 22 | `pipe(int fds[2])` | 4 KiB buffer, blocking |
| 32, 33 | `dup`, `dup2` | |
| 35 | `nanosleep(req)` | Interruptible; takes only the request |
| 39 | `getpid` | |
| 48 | `signal(sig, SIG_DFL or SIG_IGN)` | Simplified: no handler functions. Returns the old setting |
| 60 | `exit(status)` | |
| 61 | `wait4(pid, *status, opts)` | `pid = -1` for any child; `WNOHANG` supported |
| 62 | `kill(pid, sig)` | `pid > 0` one task, `0` own group, negative: group `-pid`; `sig = 0` only probes |
| 63 | `uname(buf)` | |
| 78 | `getdents(fd, buf, bytes)` | Fixed-size `struct dirent` records, including `.` and `..` |
| 79 | `getcwd(buf, size)` | Returns the length including the NUL |
| 80 | `chdir(path)` | |
| 82 | `rename(old, new)` | Replaces files and empty directories; refuses to move a directory into itself |
| 83, 84 | `mkdir`, `rmdir` | |
| 87 | `unlink(path)` | An open file survives until its last descriptor closes |
| 90 | `chmod(path, mode)` | |
| 99 | `sysinfo(buf)` | Uptime, memory, node counts, disk size |

## 11. File system and persistence

### The RAM file system

The root file system is a tree of inodes in kernel memory:

* Regular files, directories and character devices; no symbolic or hard links and no
  other mounts.
* Directory entries are kept sorted by name, so `ls` output is stable.
* Permissions: the read and write bits of a **regular file** are checked at `open`, and
  the execute bit is checked at `spawn`. There are no users or groups; everything is
  owned by root. New files get `mode & ~022`.
* Devices: `/dev/console` and `/dev/tty` (the terminal), `/dev/null`, `/dev/zero`,
  `/dev/urandom` (a xorshift generator seeded from the time-stamp counter; **not
  cryptographically secure**).
* `/bin` is rebuilt from the program table at every boot.

### Disk snapshot

If an ATA disk is present (primary bus, master, LBA28, polled PIO), `sync` writes a
snapshot to it starting at sector 0, and the next boot loads it over the freshly built
default tree. The snapshot is also written by `poweroff`, `halt`, `reboot` and when
`init` exits. Stopping QEMU with Ctrl-A X does **not** save anything.

Saved: every directory and regular file outside `/dev` and `/bin`, with mode and
contents. Not saved: devices, `/bin`, modification times (restored files get the restore
time) and open files.

Format (little endian, written by the kernel itself):

```
header (24 bytes): "ADICODOS", u32 entry count, u32 total bytes,
                   u32 checksum (rotate-left-5 and xor over the records), u32 reserved
record (repeated): u32 mode, u32 path length (with NUL), u64 data length,
                   path bytes, data bytes
```

The snapshot is padded to whole 512-byte sectors. A disk without the `ADICODOS` header
(for example a fresh zero-filled image) is treated as blank. A snapshot with a wrong
checksum is ignored with a message. The snapshot must fit on the disk (`df` shows the
capacity); otherwise `sync` fails with `ENOSPC`.

Because the default files are recreated before the snapshot is applied, a *deleted*
default file such as `/etc/motd` comes back at the next boot unless you replace it with
your own version.

```sh
rm adico.img && make     # start over with a blank disk
```

## 12. Extending Adico DOS

### Add a utility

In `adico_posix.c`, section 5:

```c
PROG(p_hello)                       /* int p_hello(int argc, char **argv, char **envp) */
{
    printf("hello from %s\n", argv[0]);
    return 0;                       /* exit status */
}
```

Then add `{ "hello", p_hello },` to `posix_progs[]` at the end of the file and rebuild;
it appears as `/bin/hello`. Rules for programs:

* Keep no mutable global state (all tasks share one address space); use locals and
  `malloc`. `errno` is the one deliberate exception, and it is safe because tasks only
  switch inside system calls.
* `printf` and `dprintf` format into a 512-byte buffer, so write long strings with
  `write_all()`.

### Add a system call

1. Add `SYS_name = N` to the `enum` in the **shared ABI block** of *both* C files (the
   blocks must stay identical).
2. Add a `case SYS_name:` to `syscall_dispatch()` in `adico_kernel.c`.
3. Add a wrapper in `adico_posix.c`, section 2, using the `SYS()` macro.
4. Run `make abi-check`.

### Add a device node

Add an enumerator to `DEV_*`, a row to the `devs[]` table in `fs_init()`, and a case to
`dev_read()` and `dev_write()`.

### Add a default file

Call `fs_text("/path", "contents")` in `fs_init()`.

### Conventions used in the code

* American English everywhere: identifiers, comments, messages, prompts and docs.
* POSIX names and semantics first; Q-DOS-style directness second (no abstraction layers
  that do not pay for themselves).
* No hidden state: kernel objects are plain structs and there is no module system.

## 13. Limitations

* **No preemption and no memory protection.** A runaway or buggy program can hang or
  corrupt the whole system. Faults inside a program are caught and turned into
  `SIGSEGV`, but a bug that corrupts the heap can still take the kernel down.
* No `fork` / `exec` (use `spawn`), no signal handlers, no job suspension.
* The shell has no control-flow constructs, functions, history, line editing, command
  substitution or word splitting.
* `grep` matches fixed strings, not regular expressions. `sort` compares bytes (no
  locale support).
* The file system is RAM backed with whole-image snapshots and no journal, so a crash
  during `sync` can lose the snapshot (the checksum then rejects it).
* One CPU only; no APIC, USB, networking or sound. Disk access is polled PIO on the
  primary IDE bus only. The PS/2 keyboard uses a US layout.
* Legacy BIOS / Multiboot boot only (no UEFI).
* Built and statically checked, but not yet booted by the author; real hardware has not
  been tried. See [Project status](#1-project-status).

## 14. Troubleshooting and debugging

| Symptom | Likely cause and fix |
|---|---|
| `Cannot load x86-64 image, give a 32bit one` | You booted `adico.elf`. Boot `adico32.elf` |
| `make` fails near `$(file ...)` | GNU make older than 4.0; upgrade |
| `abi-check` reports a difference | A type, enum or struct was changed in only one of the two ABI blocks |
| Black screen, then an immediate reset loop | A triple fault. Run with `-d int,cpu_reset -no-reboot` and look at the last exception |
| `ERR:46-B` on VGA | The CPU model has no long mode; use `-cpu qemu64` or `-cpu max` |
| No keyboard input in `run-gui` | Click the VGA window and type there; the terminal is only the serial side |
| Ctrl-C closes QEMU | You pressed it in the terminal of `run-gui`; use the window, or use `make run` |
| `sync: no disk attached` | QEMU was started without `-drive file=adico.img,format=raw,if=ide` |
| Files vanish after a reboot | The system was stopped without `sync` or `poweroff` (for example with Ctrl-A X) |
| `KERNEL PANIC` with a register dump | A kernel-level fault. Use the printed `rip=` value with `nm -n adico.elf` to find the enclosing function |

### Useful QEMU options

```sh
-d int,cpu_reset -no-reboot         # log exceptions and stop instead of resetting
-serial file:serial.log             # capture all console output (use -display none)
-s -S                               # wait for gdb on localhost:1234
```

With gdb:

```sh
gdb adico.elf -ex 'target remote :1234' -ex 'break kmain' -ex 'continue'
```

For source-level debugging add `-g` to `CFLAGS` in the `Makefile` and rebuild.

### Booting from GRUB

```sh
make iso
qemu-system-x86_64 -cdrom adico.iso -m 128M -drive file=adico.img,format=raw,if=ide
```

The generated `grub.cfg` boots `adico32.elf` through GRUB's `multiboot` command.
